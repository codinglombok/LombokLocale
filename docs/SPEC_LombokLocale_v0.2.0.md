# LombokLocale — SPEC v0.2.0

This document is the normative cross-language contract. Every language port MUST produce byte-identical output for all specified inputs. Deviations from this specification are bugs.

| References | BCP 47 (RFC 5646) and RFC 4647 (lookup); Unicode CLDR 47.0.0 (`cldr-json` tag `47.0.0`, LDML / UTS #35 Numbers, Dates and Plural Rules sections); ICU MessageFormat (syntax, DOUBLE_OPTIONAL apostrophe mode); RFC 8259 (JSON); ISO 4217 (currency codes); reviewed 2026-10-02 |

The words MUST, MUST NOT, SHOULD and MAY follow RFC 2119.

## 0. Conventions

1. All text is Unicode; positions are counted in code points.
2. A "locale" is a BCP 47 tag in text form; formatting functions never fail because of the locale (section 2.3).
3. Numbers are given as **decimal text** (section 3). A port may accept its own numeric types, which are first converted to the shortest decimal text that reads back as the same value (`f64`/`float`/`number`), `NaN`, `Infinity`, or `-Infinity`.
4. All numeric output uses Latin digits (`latn`) and the Gregorian calendar; the `-u-nu-*` and `-u-ca-*` extensions are ignored.

## 1. CLDR data

The data in use is CLDR 47.0.0. For 28 data locales — `en`, `en-GB`, `en-IN`, `id`, `ms`, `jv`, `su`, `de`, `fr`, `es`, `pt`, `pt-PT`, `it`, `nl`, `ru`, `uk`, `pl`, `tr`, `ar`, `hi`, `zh`, `zh-Hant`, `ja`, `ko`, `vi`, `th`, `sv`, `cy` — the following is taken: the `latn` number symbols (decimal, group, minus, percent, infinity, NaN), `minimumGroupingDigits`, the standard decimal, percent and currency patterns, the symbols of 14 currencies (USD, EUR, GBP, JPY, CNY, IDR, MYR, SGD, INR, KRW, SAR, AUD, THB, VND; a missing symbol falls back to the ISO code), the full/long/medium/short date patterns, the month and day names (format context, abbreviated and wide), and the Common Era era abbreviation. Cardinal plural rules (219 locales) and ordinal rules (104 locales) are taken in full. Currency fraction digits come from `supplemental/currencyData` (unknown codes: 2).

## 2. Language tags

### 2.1 Parsing

Leading and trailing spaces are ignored; `-` and `_` are separators. Empty text yields `EMPTY`. Every subtag MUST be 1-8 ASCII alphanumeric characters, otherwise `INVALID_SUBTAG` (detail: the offending subtag). Order:

1. language: 2-3 or 5-8 letters (lowercase);
2. optional script: 4 letters (first uppercase, rest lowercase);
3. optional region: 2 letters (uppercase) or 3 digits;
4. variants: 5-8 alphanumerics or 4 characters starting with a digit (lowercase); duplicate variants yield `DUPLICATE_VARIANT`;
5. extensions: a singleton other than `x` followed by at least one 2-8 character subtag (lowercase); a duplicate singleton yields `DUPLICATE_EXTENSION`; a singleton without a subtag yields `INVALID_SUBTAG`;
6. optional `x` followed by at least one private-use subtag (lowercase); `x` without a subtag yields `INVALID_SUBTAG`;
7. remaining subtags yield `INVALID_SUBTAG`.

Canonical form: the parts above joined with `-`, extensions sorted by their text. Extlangs, grandfathered tags, and tags consisting only of private-use parts are not supported (they yield `INVALID_SUBTAG`).

### 2.2 Negotiation (RFC 4647 lookup)

`negotiate(requested, available, default)`: for every requested tag in order (tags that fail to parse are skipped), try its base form (language, script, region, variants, no extensions) and then every shorter prefix. Matching against `available` is case-insensitive; the result is the `available` entry as written. Without a match the result is `default`.

### 2.3 Data locale

`data_locale(tag)`: an unparseable tag maps to `en`. For the language `zh` without script and with region TW, HK or MO, the script is treated as `Hant`. The lookup chain (section 2.2) is then matched against the 28 data locales; without a match the result is `en`. Plural rules use the same chain against the plural tables; without a match the `root` rules apply (always `other`).

## 3. Decimal text

Form: `[+-]digit+[.digit+][(e|E)[+-]digit{1,4}]`, or `NaN`, `Infinity`, `+Infinity`, `-Infinity`. An exponent with magnitude above 1000 yields `BAD_NUMBER`; any other shape yields `BAD_NUMBER` (including `1.`, `.5`, embedded spaces). The value is read exactly into a sign, integer digits (no leading zeros, at least `0`) and fraction digits (trailing zeros kept). A negative sign is kept for zero (`-0`).

## 4. Plural rules

`plural_category(locale, value)` and `ordinal_category(locale, value)` return `zero`, `one`, `two`, `few`, `many` or `other`. `NaN` and infinities yield `BAD_NUMBER`.

Operands (UTS #35): `n` the absolute value; `i` integer digits; `v` visible fraction digit count; `w` the same without trailing zeros; `f` the fraction digits as an integer; `t` the same without trailing zeros; `c` and `e` always 0. A relation `x [% m] = list` is true when `x` (after the modulus) is an integer and lies in one of the ranges; `!=` is its negation. For `n` with a non-zero fraction, `=` is always false. The first category (in the order zero, one, two, few, many) whose rule matches is chosen; otherwise `other`. Values above 10^18 without a modulus never match a range.

## 5. Number formatting

`format_number(locale, value, style, currency, min_fraction, max_fraction)`; `style` is `decimal` (default), `percent`, or `currency`.

1. Default fraction digits: decimal 0-3, percent 0-0, currency = the currency digits (min = max). When only `min` is given: `max = max(min, default max)`; when only `max` is given: `min = min(default min, max)`. The bounds MUST satisfy `0 <= min <= max <= 20`, otherwise `BAD_OPTION` (detail `fractionDigits`). Any other style yields `BAD_OPTION` (detail `style`). A currency MUST be exactly three ASCII letters (uppercased), otherwise `BAD_OPTION` (detail `currency`).
2. Percent: the value is multiplied by 100 exactly.
3. Rounding to `max` fraction digits, half away from zero; trailing zeros are then dropped down to `min` digits, or added up to `min`.
4. Grouping: from the numeric section of the positive pattern, `primary` = the last group length before the decimal point, `secondary` = the previous group length (or `primary`). Grouping is applied only when the integer digit count is at least `primary` + `minimumGroupingDigits`.
5. The pattern is split at `;` (optional negative subpattern). Affixes are the text before/after the numeric section (`#0,.`); inside an affix: `¤` is the currency symbol, `%` is the percent symbol, `-` is the minus symbol, `'text'` is a literal, `''` is an apostrophe.
6. Negative values (including `-0` and values that round to zero): the negative subpattern when present; otherwise `-` followed by the positive prefix.
7. Currency spacing (CLDR `currencySpacing`): when `¤` is the last character of the prefix, the last character of the symbol is not in Unicode categories S or Z, and the numeric text starts with a digit, insert U+00A0 after the symbol; symmetrically for `¤` at the start of the suffix.
8. `NaN` and infinities use the locale symbols as the numeric text (no grouping, no fractions).

## 6. Date formatting

`format_date(locale, date, style)`; `date` is `YYYY-MM-DD` exactly ten characters, a proleptic Gregorian date from 0001-01-01 to 9999-12-31, otherwise `BAD_DATE`; `style` is one of `full`, `long`, `medium` (default), `short`, otherwise `BAD_OPTION`. The CLDR pattern is read left to right: a run of identical ASCII letters is one field; `'...'` is a literal, `''` an apostrophe. Fields: `G` era abbreviation; `y` year (zero-padded to the width; `yy` the last two digits); `M`/`L` month (1-2 digits, 3 abbreviated, 4 wide); `d` day (zero-padded to the width); `E` weekday name (1-3 abbreviated, 4 wide). Other characters are copied verbatim. The weekday is computed from 0001-01-01 being a Monday.

## 7. MessageFormat (ICU subset)

### 7.1 Text

Text is copied verbatim except `{`, `}`, `'`, and `#` inside a plural sub-message. Apostrophes: `''` is `'`; an `'` followed by `{`, `}`, `|` or (inside plural) `#` opens a quoted run up to the next `'` (`''` inside it is `'`; an unterminated run continues to the end); any other `'` is a literal. A `}` at the top level yields `SYNTAX`.

### 7.2 Arguments

Spaces (space, tab, CR, LF) are allowed around names, types, styles and keys. Names: `[A-Za-z0-9_]+`, otherwise `SYNTAX`.

| Form | Result |
|---|---|
| `{n}` | text as-is; numbers formatted like `number` |
| `{n, number}` / `{n, number, integer}` / `{n, number, percent}` | section 5 decimal / decimal with `max = 0` / percent |
| `{d, date}` / `{d, date, full\|long\|medium\|short}` | section 6, default style `medium`; the argument must be a date text |
| `{n, plural, [offset:k] key{message} ...}` | keys `zero one two few many other` or `=decimal` |
| `{n, selectordinal, ...}` | like plural with ordinal rules, no offset |
| `{x, select, key{message} ...}` | keys `[A-Za-z0-9_]+` |

Any other type or style yields `SYNTAX`. Duplicate keys, invalid keys, missing `{`/`}` yield `SYNTAX`. A choice without `other` yields `MISSING_OTHER`. Sub-messages nested deeper than 16 levels yield `TOO_DEEP`.

### 7.3 Argument values

Arguments are text or numbers (decimal text, section 3). A missing argument yields `MISSING_ARGUMENT`. An unparseable number in `{n}`/`number`, text passed to `number`/`plural`/`selectordinal`, a number passed to `date`, an invalid date, and `NaN`/infinities passed to plural yield `BAD_ARGUMENT`.

### 7.4 Selection

`select`: the key equal to the argument text (numbers: their decimal text), or `other`. `plural`/`selectordinal`: an `=x` key whose value is numerically equal to the argument (before offset; `0` and `-0` are equal) is chosen first; otherwise the category is computed (section 4) from `argument - offset` rounded to 3 fraction digits (half away from zero) without trailing zeros; the category key is chosen, or `other`. Inside a sub-message (including a select nested in it), `#` is replaced by `argument - offset` formatted like `number`. For a non-zero offset, an argument with more than 36 digits yields `BAD_ARGUMENT`.

## 8. Catalogs and errors

`parse_catalog(json)`: the document MUST be valid RFC 8259 JSON in UTF-8 (raw lone-surrogate text or escapes, raw control characters, invalid numbers, trailing text, nesting deeper than 64 yield `BAD_JSON`), with an object at the top level (`NOT_OBJECT`), all values strings (`NON_STRING_VALUE`, detail: the key), and unique keys (`DUPLICATE_KEY`). `BAD_JSON` is checked first over the whole document; the pairs are then checked in order.

`resolve(locale, catalog, code, message_id, args)` returns `{code, messageId, text, fallback}`: when `message_id` is present and its pattern formats, `text` is the result and `fallback` is false; otherwise `text = "!!message_id!!"` and `fallback` is true.

Error codes: `EMPTY`, `INVALID_SUBTAG`, `DUPLICATE_VARIANT`, `DUPLICATE_EXTENSION`, `BAD_NUMBER`, `BAD_OPTION`, `BAD_DATE`, `SYNTAX`, `MISSING_OTHER`, `MISSING_ARGUMENT`, `BAD_ARGUMENT`, `TOO_DEEP`, `BAD_JSON`, `NOT_OBJECT`, `NON_STRING_VALUE`, `DUPLICATE_KEY`. The vectors compare codes; the human-readable error text is port-specific.

## 9. Known differences from ICU

| Case | This SPEC | ICU 77.1 | Reason |
|---|---|---|---|
| plural for an unknown locale (`xx`) | `root` rules, so `other` | the system default locale | results must not depend on the machine |
| `ru` long / `uk` medium dates | U+202F before `г.`/`р.` (cldr-json 47.0.0 data) | U+0020 | the SPEC follows the published CLDR data |
| `1e1000` | formatted exactly | infinity (ICU reader limit) | the SPEC uses exact decimal arithmetic |

## 10. Security (normative)

1. No code execution, file access, network access, or environment variables; the CLDR data is embedded in the package.
2. Inputs are bounded: subtags 8 characters, exponent 1000, message depth 16, JSON depth 64, plural operands above 10^18 without a modulus are treated as "large". Runtime is linear in the input length except for the output number length (exponent up to 1000).
3. Argument text is inserted verbatim; an application that renders the result as HTML MUST escape it itself.
4. Rust: `#![forbid(unsafe_code)]`, `no_std` + `alloc`. No runtime dependencies in any port.

## 11. Changes from 0.1.0

0.1.0 was never released; only Rust and TypeScript ran, the vector expectations were generated by Rust itself, and several rules were hand-written incorrectly. Main changes:

- plural rules are now evaluated from CLDR 47 data for every locale (previously a hand-written list; wrong examples: `pl` 21 mapped to one, `hr` 5 to many, no `many` for millions in `fr`/`es`/`pt`);
- numbers, currencies and dates use CLDR patterns, symbols, currency digits and month/day names (previously: dates only for `en`/`id`, currency symbols in front for `de`/`es`, JPY with two decimals);
- percent style and Indian/minimum grouping added;
- MessageFormat: apostrophes, offset, `=n`, `number`, `date`, locale-formatted `#`, coded errors;
- BCP 47: stricter extensions, private use, variants and errors; negotiation is a plain RFC 4647 lookup (`zh-TW` is no longer tried before `zh` for `zh-Hant-TW`);
- strict JSON catalogs (duplicates, surrogates, depth);
- the Python, Go and PHP ports implemented; the CLDR data license (Unicode License v3) recorded in `LICENSE-UNICODE` and `NOTICE`.

To regenerate the vector file: `python3 vectors/build_vectors.py` (writes `vectors/lomboklocale-vectors-v1.json` deterministically), then refresh `vectors/SHA256SUMS` with `sha256sum`. The ICU cross-check runs with `node vectors/check_icu.mjs` and skips itself when the local ICU ships a CLDR version other than 47.
